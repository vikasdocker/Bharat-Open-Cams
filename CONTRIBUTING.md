# Contributing

## Workflow
1. Inspect the repository, current branch, docs and relevant tests before editing.
2. Open an issue or write down the scope and acceptance criteria.
3. Create a focused feature branch; do not force-push or overwrite shared history.
4. Make small, reviewable changes.
5. Run relevant validation (schema checks, tests, lint/build and security checks).
6. Inspect the complete diff for regressions, secrets, unsafe endpoints and policy violations.
7. Open a pull request with scope, checks performed, risks and screenshots/logs when useful.
8. Merge, deploy or publish only with explicit maintainer approval.

## Feed submissions

A submission must include the official publisher, source page, terms/licence, permission evidence, attribution, viewing method and verification date. Submissions without credible authorization evidence must remain pending and must not be added to the public catalog.

Do not submit arbitrary exposed CCTV URLs or feeds found through scanning/dorking. Do not submit credentials or tokens.

## Quality bar
- Keep docs accurate and clearly distinguish planned from implemented features.
- Add tests for new validation and behavior.
- Minimize permissions and user data collection.
- Include accessibility, mobile performance and failure-state considerations.
- Never claim tests, publication, or deployment succeeded unless the result was verified.
